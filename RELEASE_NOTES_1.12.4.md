# OLI 1.12.4 — туннель включается сам, первый запуск настраивается за минуту

Главное: **туннель больше не «не поднимается»**. OLI сам скачивает всё, что для него нужно,
и при первом запуске показывает понятную проверку подключения вместо загадочной ошибки.

## Почему туннель не работал

Туннелю нужен файл `cloudflared.exe`, которого в сборке не было. Программа запускала его,
получала «файл не найден» и заканчивала одной строкой «cloudflared.exe не найден» — а
пользователь оставался с телефоном, который подключается только по домашнему Wi-Fi.

Теперь:

| Раньше | Сейчас |
|---|---|
| `cloudflared.exe` нужно было найти и положить вручную | OLI **скачивает его сам** при первом запуске (около 20 МБ, один раз) |
| Нет интернета к GitHub — тупик | пробует **зеркало**, потом честно говорит «включите VPN» |
| Скачался битый файл / страница от провайдера | проверяются **размер, заголовок программы и SHA-256**; битое не запускается |
| Одна попытка запуска, потом ошибка | при отсутствии адреса — **вторая попытка** с обычными флагами cloudflared |
| Провайдер блокирует QUIC/UDP | по умолчанию **IPv4 + http2** — работает на мобильных сетях и в вузах |
| Туннель упал ночью — тишина | **watchdog**: замечает падение за 20 с и поднимает заново (до 3 раз) |

## Первый запуск: установка и мини-тест

При первом старте `OLI.exe` открывается окно **«Настройка OLI»**, которое:

1. **ставит компоненты** — скачивает cloudflared и проверяет его;
2. **запускает сервер** и **открывает порт** в брандмауэре (с запросом UAC, если нужно);
3. **поднимает туннель** и проверяет, что публичный адрес реально открывается;
4. прогоняет **мини-тест подключения** — ровно те же вопросы, что задаёт телефон:
   - отвечает ли сервер на порту;
   - отвечает ли он по адресу Wi-Fi (единственная честная проверка брандмауэра);
   - работает ли адрес из интернета;
5. показывает **готовый код для телефона** и итоговую фразу:
   *«Всё готово: OLI работает, телефон подключится и дома, и на мобильном интернете»*.

Если что-то не так — у каждой строки есть **причина и кнопка**:
«Открыть порт», «Запустить сервер», «Повторить», «Журнал туннеля».

Повторно открыть этот мастер можно в любой момент: **«Пульт админа» → «🧰 Установка и проверка»`.
Уже установленное заново не скачивается.

## Стабильность

- сервер, поднятый для проверки, **освобождает порт** перед запуском основного — больше нет «порт занят» после успешной настройки;
- туннель, поднятый при настройке, **передаётся** главному окну и остаётся живым;
- закрытие приложения закрывает туннель: публичный порт не остаётся открытым «сам по себе»;
- если туннель перезапустился сам, OLI выдаёт **новый код подключения** вместо мёртвого адреса.

## Проверки

`OLI.SelfTest` — **169 проверок**, добавлены:
- компоненты: обрезанный файл, HTML-страница под видом `.exe`, несовпадение SHA-256, зеркало, отсутствие «мусора» после неудачной загрузки;
- мини-тест: сервер молчит (кнопка «Запустить сервер»), локально работает а брандмауэр закрыт (кнопка «Открыть порт»), туннель не отвечает (кнопка «Журнал туннеля»), нет Wi-Fi (предупреждение, не ошибка), туннель выключен (пропуск, не ошибка).

## Как обновиться

1. Скачайте `OLI.exe` (или `OLI-win-x64.zip`), закройте OLI, распакуйте поверх.
2. Запустите — откроется «Настройка OLI». Дождитесь «Всё готово» и нажмите «Начать работу».
3. Телефон: `OLI-Mobile-1.12.4-release.apk` (обновление поверх).
4. Дома телефон найдёт ПК сам по маяку. Вне дома — на ПК «🌍 Дам доступ из интернета», затем на телефоне Настройки → «Вставить код».

> Первый запуск качает cloudflared с GitHub: если провайдер блокирует GitHub, включите VPN на одну минуту — OLI попробует зеркало сам.
