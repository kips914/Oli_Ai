# OLI 1.12.3 — ядро подключения и чаты переписаны

Большое обновление «под капотом»: подключение к серверу и чаты больше не написаны
по-разному в четырёх местах. Теперь у ПК, сервера и телефона **одни и те же правила**,
и эти правила проверяются автоматическими тестами на каждом билде.

## Что было не так

| Было | Чем это ломалось |
|---|---|
| Каждое место само решало «сервер доступен?» | ПК показывал «подключено», хотя движок модели лежал, и чат падал |
| Поиск сервера сканировал 254 адреса на порту 8765 | Порт 6767 не находился вообще; на мобильном интернете поиск невозможен |
| Код подключения собирался на ПК и разбирался на телефоне по-разному | Пробел из мессенджера или префикс `oli://` ломал вставку |
| Каждое сообщение перезаписывало весь файл чатов | Две одновременные записи теряли сообщения |
| Поздний ответ мог «оживить» удалённый чат | Удалённый чат возвращался сам |
| Ответ без текста не показывался | Казалось, что OLI не ответил |

## Что сделано

### Одно ядро подключения (`ConnectionCore`)
- нормализация адреса: `192.168.1.10:6767`, `HTTP://LOCALHOST:6767`, `https://x.trycloudflare.com` приводятся к одному виду;
- код подключения `OLI1|адрес|invite` собирается и разбирается **одной** функцией; кроме кода принимается и просто адрес;
- **одно правило здоровья**: `Ready` / `EngineDown` / `NotOli` / `ServerDown`, с человеческой фразой для каждого;
- единый бюджет повторов: проба — 3 попытки, сообщение — 2, а `503` (движок выключен) не повторяется никогда;
- маяк `OLI-BEACON/2` раз в 2 секунды: телефон узнаёт **реальный порт** и имя ПК без сканирования сети.

### Одно ядро чатов (`ChatCore` + `ChatStore`)
- один формат сообщения: `id`, роль, текст, время, файлы, ошибка, «печатает…»;
- заголовок чата — из первого сообщения, одна строка, обрезка с «…»;
- история для модели — без ошибок, пустых и системных сообщений, последние 24;
- хранилище: блокировка на аккаунт, один кэш, атомарная запись через `.tmp` → переименование;
- ответ, пришедший после удаления чата, больше **не создаёт** чат заново: сервер отвечает `409 {deleted:true}`, приложение честно об этом говорит.

### Приложение на телефоне
- сообщения отправляются строго по одному (без гонки и `429`), «печатает…» честно ждёт;
- если вы переключились на другой чат, пока модель думала, ответ не попадает в чужой чат;
- пустой ответ модели показывается явной фразой, а не пустым пузырём;
- поиск сервера: сначала UDP-маяк (порт любой), потом скан подсети — только как запасной вариант;
- код подключения разбирается теми же правилами, что на ПК (пробелы, `oli://`, простой адрес).

### Пульт админа на ПК
- кнопка **«📱 Проверить путь телефона»** — проверяет сервер ровно так, как это делает телефон: запущен ли сервер, открыт ли порт в брандмауэре, отвечает ли каждый адрес Wi-Fi, работает ли движок, живой ли интернет-адрес. Каждый шаг — отдельной строкой.
- в блоке кода подключения теперь видно и **домашний адрес** (для одного Wi-Fi), и код для интернета.

## Тесты

`OLI.SelfTest` в CI теперь проверяет **128+ утверждений**, в том числе:
- нормализацию адресов, код подключения, разбор «грязной» вставки;
- классификацию здоровья (движок жив / движок выключен / чужой сервис / тишина);
- маяк: кодирование, порт, имя, чужие UDP-пакеты;
- чаты: заголовки, обрезку, историю для модели, «пустой ответ», сохранность при параллельной записи, отсутствие «оживления» удалённого чата;
- **живой сервер**: поднимается настоящий Kestrel на свободном порту и проходится весь путь телефона — `/api/health` → регистрация → вход (в том числе неверный пароль = 401) → `/api/chat` (без движка = 503 с понятной причиной, а не 500) → список чатов → чтение чата → отказ без токена.


## Исправлено после проверки кода (в этом же релизе)

Внимательный разбор всех файлов нашёл ошибки, которые сборка и прежние тесты не ловили:

| Проблема | Что было | Стало |
|---|---|---|
| Модель помнила чужой чат | контекст сессии был один на аккаунт: открыли другой чат — OLI отвечал с учётом предыдущего | `AgentSession.UseThread`: при смене чата история заменяется историей этого чата |
| Удалённый чат «возвращался» | сервер создавал новый чат под старым id | `/api/chat` и `/api/vision` отвечают `409`, чат не пересоздаётся |
| 500 «Collection was modified» | чтение отдавало живой список, а в него в это время писали | чтения возвращают снимок под блокировкой |
| «Чат удалён» при пустом ответе модели | пустой ответ и удалённый чат считались одним и тем же | пустой ответ = `502` с понятной фразой, удалённый чат = `409` |
| Фото с телефона исчезало из истории | `/api/vision` не писал в тред | фото и ответ сохраняются в чате |
| Вечная «печатает…» | при переключении чата `busy` не сбрасывался | сбрасывается всегда |
| После перезапуска — пустой экран | последний чат не открывался | приложение открывает последний разговор |
| Два маяка из одного процесса | ПК и сервер рассылали свой пакет | рассылает только сервер |
| Маяк терял подсеть | ошибка глобального броадкаста отменяла остальные | ошибки изолированы, порт находится в любом режиме |
| «Проверить всё» не искал заново | при неудаче сразу говорил «не ответил» | переискивает сервер по маяку (IP ПК мог измениться) |

Тестов теперь **153** — добавлены проверки на каждый пункт из таблицы, включая живой HTTP-сценарий «отправить в удалённый чат».

## Как обновиться

1. Скачайте `OLI.exe` (или `OLI-win-x64.zip`) из этого релиза, закройте старый OLI, распакуйте поверх.
2. На ПК: «Пульт админа» → **«🛡 Открыть порт»** → в UAC «Да».
3. Телефон: `OLI-Mobile-1.12.3-release.apk` → установить (обновление поверх старой версии).
4. Дома: телефон сам найдёт ПК по маяку — адрес вводить не нужно.
5. Вне дома: на ПК «🌍 Дам доступ из интернета», затем на телефоне Настройки → «Вставить код».
6. Если не подключается — на ПК нажмите **«📱 Проверить путь телефона»**: там будет видно, что именно мешает.
