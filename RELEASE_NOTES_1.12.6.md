# OLI 1.12.6 — OLI.exe снова открывает окно

В 1.12.5 при запуске `OLI.exe` мог не появиться ни один экран: процесс в диспетчере
задач есть, окна нет, и ничего не происходит. Виноват мой же код из 1.12.5 —
синхронное ожидание сетевой проверки порта на потоке интерфейса.

## Что было

```
OnStartup  ──►  Task.Run(...).Wait(3 c)  ──►  PortGuard.OliAnswersAsync
                                                     │
                                            await захватывает WPF-контекст
                                                     │
                                            продолжение ждёт UI-поток
                                                     │
                                            UI-поток ждёт .Wait()  ⟳ вечно
```

Порядок «проверить, не работает ли уже OLI» нужен, чтобы не открывать мастер
настройки поверх живого сервера. Проверка — сетевая, то есть асинхронная. Вызов её
через `GetAwaiter().GetResult()` на потоке интерфейса останавливал этот поток, а
продолжение `await` не могло на него вернуться — классический дедлок.

## Что исправлено

1. **Проверка порта больше не блокирует интерфейс.** Она идёт на пуле потоков, с
   ограничением 700 мс на запрос и жёстким дедлайном 3 с. Любое сомнение трактуется
   как «не отвечает» — то есть худший исход теперь «откроется мастер настройки»,
   а не «не откроется ничего».
2. **Сторож запуска.** Если через 10 секунд после старта окно так и не появилось,
   OLI пишет об этом в лог и показывает сообщение с кнопкой «открыть папку с логом».
   Никакой больше тишины.
3. **Окно возвращается на экран.** WPF помнит положение окна; если монитор отключили
   или убрали док-станцию, окно открывалось за пределами рабочего стола — процесс
   работает, окна нет. Теперь позиция проверяется и при необходимости
   центрируется, свёрнутое окно разворачивается.
4. **Мастер настройки защищён от двойного клика.** Второй клик по «Начать работу»
   приводил к повторному сохранению, повторному освобождению порта и падению
   `DialogResult can be set only after Window is created and shown` — приложение
   закрывалось сразу после настройки.
5. **Закрытие мастера не подвешивает приложение.** Освобождение порта при закрытии
   окна крестиком выполняется в фоне, а не в UI-потоке.

## Как проверить, что дело не в OLI

Лог теперь пишет этапы старта:

```
APP  Старт OLI 1.12.6 (Microsoft Windows NT 10.0.22631.0)
APP  Первая настройка пропущена или завершена — открываю главное окно
APP  Окно OLI открыто
```

Файл лежит в `%LOCALAPPDATA%\OLI\logs\oli.log` (путь указан в сообщении сторожа).

## Проверки и сборки

- 187 автоматических проверок, включая новые: проверка порта укладывается в дедлайн
  даже на адресе, который принимает соединение и молчит, и на закрытом порту
  возвращает «нет» вместо исключения.
- `OLI.exe` собирается тем же конвейером и проходит самопроверку в CI.
- Номер сборки Android: 18 (1.12.6).

## Если окно всё равно не появляется

1. Посмотрите `%LOCALAPPDATA%\OLI\logs\oli.log` — последние 20 строк назовут этап.
2. Проверьте, не висит ли процесс OLI из прошлой версии: диспетчер задач → завершить
   `OLI.exe`. Старая копия держит единственный экземпляр и показывает вместо окна
   сообщение «OLI уже запущен».
3. Запустите `OLI.exe` ещё раз — если окно было за пределами экрана, оно уже
   центрируется само.
